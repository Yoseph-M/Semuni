Semuni — Phase 3 authorization check

This page talks directly to a running Semuni backend (npm run start:prod in backend/) and exercises the authorization rules added in Phase 3: object-level access to trips and payments, driver-only withdrawals, UUID validation, and scoped idempotency keys. It runs against your development database and creates two uitest_* passengers plus a few trips/payments, so point it at dev — never production.
